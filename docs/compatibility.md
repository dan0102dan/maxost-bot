# Совместимость

## Чаты и направления

`DIALOG`, `CHAT`, `CHANNEL` MAX привязываются по ID аккаунта и чата, не по имени.
Групповые сообщения содержат имя автора. Каналы без прав публикации доступны
для чтения; окончательное решение о правах всегда принимает сервер MAX.
Собственные MAX-сообщения подавляются намеренно; отправленные мостом анонимные
публикации дополнительно узнаются по клиентскому ID (CID).
Для чужих анонимных публикаций без sender нельзя достоверно определить автора.

История до первого подключения не переносится. Периодическая сверка восстанавливает
сообщения после сохранённой точки; при неполной пагинации точка не сдвигается.
Удаления/редактирования давно исчезнувших исходников нельзя гарантированно восстановить.

## Форматирование

Жирный, курсив, подчёркивание, зачёркивание, моноширинный текст, блок кода,
цитаты и ссылки передаются явными entities, включая вложенные диапазоны и UTF-16.
Текст не пропускается повторно через Markdown: буквальные `*`, `_`, `[]` не меняются.
При разбиении длинного текста диапазоны обрезаются и смещаются без разрыва emoji.

MAX-заголовок отображается жирным. Telegram-спойлер, custom emoji, язык блока кода
и сворачиваемость цитаты не имеют полного эквивалента в закреплённом MAX API:
текст остаётся, отсутствующая возможность обозначается пометкой.
Упоминание Telegram-пользователя становится ссылкой на него, а не на чужой MAX ID.
Неизвестный тип вложения/форматирования явно обозначается текстом.

## Медиа и редактирование

Фото, видео, документы, голосовые — до 20 МБ. Альбом Telegram собирается
в PostgreSQL после 1,5 секунды тишины, затем отправляется одним MAX-сообщением.
Поздний элемент/правка обновляет этот объект; буфер переживает перезапуск.
MAX-альбом отправляется через `sendMediaGroup` (2–10 совместимых элементов);
несовместимые типы и группы свыше 10 элементов делятся по правилам Telegram.

Правки используют `editMessageText`, `editMessageCaption`, `editMessageMedia` и
MAX `MSG_EDIT`. При росте длинного текста добавляются только новые части,
при сокращении лишние удаляются; неизменные ID сохраняются.
Число элементов существующего Telegram-альбома нельзя изменить одним API-вызовом:
такой альбом пересобирается автоматически, старый удаляется после подтверждения нового.
Медиа → текст и замена стикера тоже могут требовать замены сообщения.
Удаление старых частей подчиняется ограничениям Telegram по времени/правам;
ошибка видна в очереди, подтверждённые шаги при повторе не выполняются заново.

Стикер MAX отправляется нативным `sendSticker`; несовместимая анимация остаётся
явно подписанным файлом. Произвольный стикер Telegram не имеет ID в наборе MAX:
статичный передаётся изображением, TGS/WebM — исходным файлом с пометкой.
Звонки и исчезающие сообщения не копируются; последние обозначаются текстом.

## Реакции и опросы

Реакции MAX показаны карточкой со счётчиками, без имитации чужих Telegram-аккаунтов.
`/react` ответом на связанное сообщение открывает кнопки добавления/снятия реакции
**от вашего MAX-аккаунта**. Собственная реакция исключена из зеркалируемых счётчиков.
Нативные Telegram reaction updates обрабатываются, когда платформа их предоставляет;
в личном чате их доставка не гарантирована, поэтому есть командный интерфейс.
Typing и read receipts намеренно не реализованы.

Входящий опрос — карточка с настоящими MAX-результатами, single/multiple выбором,
отзывом голоса (если разрешён) и обновлением результатов. Кнопки действуют на исходный
MAX-опрос, а не создают независимую Telegram-копию голосования.
Закрытый опрос голосовать не позволяет. После изменения вариантов старые кнопки
отвергаются. Регулярный Telegram-опрос создаёт MAX-опрос; голосование в MAX затем
доступно в карточке, не через голоса исходного Telegram-опроса.
Викторина Telegram без известного правильного ответа и опрос с медиа-вариантами
не отправляются: бот объясняет несовместимость. Свежие результаты доступны по кнопке
обновления; импорт голосов от имени других участников не выполняется.

## Доставка и сессии

Подтверждённые удалённые операции имеют зашифрованные контрольные точки. Все ID частей
альбома связаны с исходником. Неопределённая отправка останавливается до решения
владельца, поскольку API не обеспечивает транзакцию сразу между двумя мессенджерами.
Это не обещание exactly-once при потере ответа сервера.

Отозванная/недействительная сессия получает `reauth`: соединение закрывается,
локальный токен удаляется, владельцу отправляется уведомление. Неудавшееся уведомление
повторяется после восстановления Telegram. Восстановление процесса не запрашивает SMS;
новый вход инициирует только пользователь. `/disconnect` удаляет старые привязки
и очередь; сохранённые в Telegram темы вручную удаляются пользователем.

MAX wire-адаптер изолирован в `max_transport.py`. Совместимость проверяется с PyMax
`53103f0c8df32f36110cbe0bcbfc3ad82173808a` (2.4.1): explicit entities, payload-модели,
MSG_SEND/MSG_EDIT, PollFlags, реакции. При обновлении зависимости обязательны контрактные
тесты и живой тест с двумя владельцами.
