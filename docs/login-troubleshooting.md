# Вход в MAX

`/connect` → согласие → международный номер → **Получить код** → код → пароль 2FA, если MAX его запросил.

Сам ввод цифр не отправляет запрос. Экран ввода кода открывается только после ответа MAX на `AUTH_REQUEST`. Фраза «MAX принял запрос кода» не подтверждает доставку SMS оператором. Длина кода берётся из ответа MAX.

## Код не приходит

1. Проверьте номер и код страны на экране до нажатия «Получить код».
2. Посмотрите, на каком этапе остановился вход: подключение, запрос кода или ожидание ввода. Ошибка содержит безопасную категорию и ID попытки.
3. На сервере:

```bash
docker compose logs --since=10m bot | grep 'MAX auth'
docker compose exec bot python -m maxost.diagnose
```

Диагностика проверяет локальную конфигурацию PyMax, соединение и handshake. Она **не использует аккаунты, не запрашивает SMS и не авторизуется**. Для проверки без сети добавьте `--offline`.

| Категория | Что проверять |
|---|---|
| `DNS`, `TLS`, `CONNECTION`, `NETWORK_TIMEOUT` | Сеть/DNS/сертификаты внутри контейнера и доступность MAX с сервера |
| `CLIENT_COMPATIBILITY` | Совместимость закреплённого PyMax с текущим протоколом MAX |
| `RATE_LIMIT`, `REQUEST_REJECTED`, `PHONE_REJECTED` | Отказ MAX; не повторять запросы кодов подряд |
| `INPUT_TIMEOUT` | Истёк срок ввода; `/connect` начинает новую попытку |

Номер, код, пароль, токены и сырые ответы MAX в диагностические логи не пишутся. Для разбора ошибки достаточно категории, этапа и ID попытки. Не включайте DEBUG-логи PyMax для пользовательских аккаунтов.

После перезапуска сохранённая сессия используется без запроса SMS. Отозванная сессия остаётся отключённой до явного повторного входа владельца.
