# Эксплуатация

## Проверка перед открытой регистрацией

Сначала задайте `ALLOWED_TELEGRAM_IDS` для двух тестовых пользователей. Проверьте:

- вход по SMS и QR;
- личный диалог, группу и канал;
- текст, файлы, альбомы, стикеры и редактирование;
- обычный и множественный опрос;
- реакции;
- отзыв сессии MAX и повторный вход;
- перезапуск контейнера с сообщением в очереди.

Реальные аккаунты и токены не используются в CI.

## Автотесты

```bash
python -m pip install . -r requirements-dev.txt
ruff check maxost tests
pytest -q
```

PostgreSQL-тесты требуют **одноразовую тестовую БД** через `TEST_DATABASE_URL`:
тесты очищают её таблицы. GitHub Actions использует PostgreSQL 17 и собирает Docker.

## Резервные копии

Сохраняйте PostgreSQL и `.env` отдельно. Ключи `ENCRYPTION_KEYS` перечисляются
через запятую: первый шифрует новые записи, остальные нужны для чтения старых.
Не публикуйте `.env` и не включайте payload-логи PyMax в production.

## Диагностика

`/status` показывает только полезное состояние. Если доставка не подтверждена,
бот покажет номер задания и команды `/retry N` или `/skip N`.

После неопределённого результата `/retry N confirm` может создать дубль — сначала
проверьте MAX и Telegram. Если создание топика оборвалось в неопределённый момент,
бот подскажет `/bind UUID`.

При отзыве сессии бот останавливает подключение и просит войти снова. SMS без действия
пользователя не запрашивается. Один процесс удерживает advisory lock; второй экземпляр
приложения не запускается.
