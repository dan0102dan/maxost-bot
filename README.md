# MAXOST

**Ваш MAX — в Telegram.** Диалоги, группы и каналы разложены по темам одного бота.

![CI](https://github.com/dan0102dan/maxost-bot/actions/workflows/test.yml/badge.svg)

Каждый пользователь подключает свой аккаунт. Вход — по SMS или QR; сессии,
очередь и привязки пользователей хранятся изолированно.

## Возможности

- Сообщения и файлы в обе стороны; группы показывают автора, каналы учитывают права MAX.
- Альбомы, ответы, форматирование, редактирование текста и медиа.
- Опросы с голосованием в оригинале MAX, реакции и стикеры.
- Неизвестные вложения не теряются: бот показывает явную текстовую пометку.
- PostgreSQL, зашифрованные MAX-сессии, очередь доставки и восстановление после рестарта.

**Так задумано:** написанное владельцем непосредственно в MAX не дублируется;
история до первого подключения не импортируется. Typing/read receipts не передаются.

## Запуск

В **@BotFather** включите темы в личных чатах. У токена не должно быть другого
получателя updates или webhook.

```bash
git clone https://github.com/dan0102dan/maxost-bot.git
cd maxost-bot
python3 scripts/configure.py
docker compose up -d --build
```

Откройте бота → `/start` → введите номер. Можно запросить SMS или сразу выбрать
**«Войти по QR»**. Если SMS уже запрошена, кнопка **«Код не пришёл — войти по QR»**
переключает ту же попытку без второго SMS-запроса.

QR отправляется отдельным защищённым сообщением. После подтверждения QR-сессия
сохраняется как web-сессия и после рестарта восстанавливается через `WebClient`.

Для закрытого тестирования:

```dotenv
ALLOWED_TELEGRAM_IDS=123,456
```

Пустое значение открывает регистрацию всем. По умолчанию — до 100 аккаунтов,
файлы до 20 МБ.

Обновление:

```bash
git pull --ff-only
docker compose up -d --build
```

Миграции применяются автоматически. Не удаляйте PostgreSQL volume и `.env`.

## Команды

| Команда | Действие |
|---|---|
| `/connect`, `/status`, `/disconnect` | Вход, состояние, отключение и удаление данных |
| `/react`, `/poll` ответом | Реакции или результаты MAX-опроса |
| `/delete` ответом | Удалить своё сообщение из MAX |
| `/retry N`, `/skip N` | Повторить или пропустить доставку |
| `/cancel`, `/help` | Отменить ввод, открыть справку |

При неизвестном результате отправки нужен `/retry N confirm`: повтор может
создать дубль. При отзыве MAX-сессии бот просит войти заново и сам SMS не запрашивает.

## Важно

**0.2 / alpha.** Используется неофициальный PyMax. Протокол MAX может измениться,
а аккаунт — получить ограничения.

Оператор сервера технически имеет доступ к сессиям и пересылаемым данным.
Шифрование БД не является E2E. SMS-коды не сохраняются; сообщение с 2FA-паролем
бот пытается удалить после получения.
