# MAXOST

**Ваш MAX — в Telegram.** Диалоги, группы и каналы разложены по темам одного бота.

![CI](https://github.com/dan0102dan/maxost-bot/actions/workflows/test.yml/badge.svg)

Каждый пользователь подключает свой аккаунт. Вход — через цифровую клавиатуру
RichMessage; переписка и настройки других пользователей недоступны.

## Возможности

- Сообщения и файлы в обе стороны; в группах виден автор, в каналах учитываются права публикации.
- Альбомы, подписи, ответы, форматирование, редактирование текста и медиа.
- Опросы с голосованием **в оригинале MAX** и карточки реакций.
- Стикеры; несовместимые форматы передаются с явной пометкой, а не теряются.
- Зашифрованные сессии и очередь PostgreSQL, восстановление после перезапуска,
  уведомления об ошибках и отзыве сессии.

**Так задумано:** написанное вами непосредственно в MAX не дублируется;
история до первого подключения не импортируется. Typing/read receipts не передаются.

## Запуск в Docker

В **@BotFather** включите темы в личных чатах. Для токена не должно быть другого
получателя обновлений или webhook.

```bash
git clone https://github.com/dan0102dan/maxost-bot.git
cd maxost-bot
python3 scripts/configure.py
docker compose up -d --build
```

Скрипт запросит токен без отображения и создаст `.env` с паролем БД и ключом
шифрования. Откройте бота → `/start` → подключите MAX.

Для закрытого тестирования укажите `ALLOWED_TELEGRAM_IDS=123,456`;
пустое значение открывает регистрацию всем. По умолчанию — до 100 аккаунтов,
файлы до 20 МБ, срок хранения технических данных — 30 дней.

```bash
docker compose logs --tail=100 -f bot
# Обновление: предварительно сохраните БД и .env.
git pull --ff-only
docker compose up -d --build
```

Миграции применяются автоматически; версия 0.2 сохраняет существующие привязки
тем и очередь версии 0.1. Не удаляйте volume PostgreSQL при обновлении.

## Управление

| Команда | Действие |
|---|---|
| `/connect`, `/status`, `/disconnect` | Вход, состояние, отключение с удалением данных |
| `/react`, `/poll` ответом на сообщение | Реакции или результаты исходного MAX-опроса |
| `/delete` ответом на своё сообщение | Удалить его из MAX; для альбома — весь объект |
| `/retry N`, `/skip N` | Повторить или пропустить неудачную доставку |
| `/cancel`, `/help` | Отменить ввод, открыть справку |

При неопределённом результате отправки нужен `/retry N confirm`: повтор может
создать дубль. При отзыве сессии бот уведомит о повторном входе, но не запросит SMS сам.

## Важно

**0.2 / alpha.** Используется неофициальный PyMax: протокол может измениться,
аккаунт — получить ограничения. Проверяйте обновления на тестовых аккаунтах.

Оператор сервера технически имеет доступ к сессиям и пересылаемой переписке.
Шифрование БД не является сквозным. SMS-коды не сохраняются в БД; сообщение
с 2FA-паролем бот пытается удалить, но Telegram уже получил его текст.
**Храните резервную копию `.env` отдельно от БД и не публикуйте секреты.**

Один активный процесс обслуживает пользователей; горизонтальное масштабирование
не включено. [Совместимость форматов и доставка](docs/compatibility.md) ·
[Эксплуатация и тестирование](docs/operations.md)
